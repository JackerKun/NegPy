# 相机翻拍

> **简体中文翻译** · 译自 [`docs/CAMERA_SCANNING.md`](../CAMERA_SCANNING.md) · 对应 NegPy v0.58.0 · 若有出入，以英文原文为准

**相机翻拍**选项卡使用联机相机翻拍底片，并直接导入 NegPy。不需要单独的拍摄应用，也不用在文件夹之间搬来搬去。它有两种模式，并根据检测到的硬件在两者之间自动选择。

---

## 它能做什么

**普通相机翻拍。** 在你使用的任何光源下对画幅进行一次曝光，作为普通 RAW 导入，并像其他任何文件一样处理。这只需要一台受支持的相机。

**窄带 RGB 扫描。** 连接 RGB [Scanlight](https://github.com/jackw01/scanlight) 后，光源依次闪红、绿、蓝，相机每个通道各拍一张。NegPy 的**三色扫描**合并对三个 RAW 做亚像素对齐，并在反转之前合成一帧。

三张胜过一张，因为单次宽带曝光会让每个染料层污染相邻通道。绿色拜耳滤镜是三者中最宽的，因此它同时捕捉到红光和蓝光的泄漏。一次一个窄带从原理上消除了这种串扰，并且每个通道都获得传感器的完整动态范围，而不是彼此分摊。

## 你需要什么

| | |
|---|---|
| **相机** | 任何 [libgphoto2 能驱动](http://gphoto.org/proj/libgphoto2/support.php)、具备实时取景和远程拍摄的机身。不在该列表中的机身通常仍可通过通用 PTP 驱动工作。a7C II 就可以。 |
| **python-gphoto2** | 可选依赖，自由软件（LGPL）。`pip install gphoto2`。 |
| **Scanlight**（可选） | 仅窄带 RGB 需要。普通相机翻拍无需它。 |

**没有这些，NegPy 也照常运行良好。** 缺少 python-gphoto2 时，相机翻拍选项卡显示一行安装提示，NegPy 的其他所有部分不受影响。不涉及任何专有组件：libgphoto2 是 LGPL，不捆绑、不链接、也不要求任何厂商 SDK。

> ⚠️ **仅限 macOS 和 Linux。** libgphoto2 没有 Windows 构建，因此没有 Windows wheel，该选项卡也无法在 Windows 上连接。

## 设置

```bash
uv sync --group camera     # or: pip install gphoto2
```

这就是全部安装步骤。libgphoto2 随 wheel 一起分发，因此没有别的要下载、构建或放置的东西。如果你自己打包应用，请在 `make build` 之前运行同一条命令。构建随后会捆绑 libgphoto2 的相机驱动。跳过它，打包后的应用就会显示安装提示。

然后将相机置于 **PC Remote** 模式，并通过 USB 连接。NegPy 会自动检测它。没有地址要输入，没有登录，也没有配对。

> 在 macOS 上，只要没有其他程序持有 PTP 相机，系统相机守护进程就会立即占用它，而且几分钟内不会放手。因此，NegPy 在相机翻拍面板看到机身的那一刻就取得占用权并一直保持：只要该面板打开，相机就属于 NegPy，Preview、Photos、Image Capture 及其他联机软件都无法使用它。拔下线缆即交还。
>
> 唤醒该守护进程的是任何请求相机的应用，而且它不一定是你打开的。常见情形是后台同步客户端，静默且反复地请求：如果相机显示为使用中而表面上没有任何程序在运行，请先检查这类应用。

## 扫描

**构图与对焦。** 打开**实时取景与扫描**。在图像上任意位置单击，把相机的*硬件*对焦放大镜对准该处。再次单击返回完整帧。在白光和普通（仅相机）扫描中，你可以从工具栏实时设置 ISO、快门和光圈。使用已校准的 RGB 预设时，这些控件被隐藏，改为锁定到预设（见**预设**），扫描因此不会漂移。机身无法提供的控件会置灰。没有电子光圈的镜头上的光圈就是常见情形——大多数放大镜头和微距镜头都是如此。

**校准（RGB 模式）。** 设置你扫描时将使用的 ISO 和光圈。按预设下拉菜单旁的 **+**，将小矩形放在通透的片基上，为预设命名并运行。帧与帧之间的片边是理想目标。校准对该区块测光，并解算出一个共享快门加逐通道 LED 亮度，使每个通道都落在刚好低于溢出的位置。它会将 ISO 和光圈一并记录。

这个高光位置很重要，因为通透片基在反转之后成为*黑点*。因此有一个溢出保护会检查原始拜耳感光单元，并在任何通道饱和时回退曝光。每种胶片型号保存一次预设，然后重复使用。

如果你的曝光设置无法达到目标，运行会在探测阶段停止。弹出窗口会说明往哪个方向调整：曝光过度意味着缩小光圈或降低 ISO，曝光不足意味着开大光圈或提高 ISO。**不会保存任何预设。** 在保持打开的窗口中调整并重新校准。

**预设。** 选定的预设以只读方式显示，连同其 RGB 亮度、ISO、快门和光圈。扫描在每帧之前将该曝光强制写入机身，因此碰乱的拨盘无法歪曲结果。要改为手动构建预设，从下拉菜单中选择**手动创建预设…**。滑块和曝光步进器随即解锁。调好数值，然后按保存（软盘）按钮为预设命名并保存。白（White）只是白光预设的通道，因为 Scanlight 无法将它与 RGB 一起点亮。

**扫描。** 选择输出文件夹和预设，然后每帧按一次**扫描**。文件落在按胶卷划分的子文件夹中，自动编号，并自动导入和合并，因此快门之后片刻就会出现反转好的正像。**重拍**重新拍摄当前帧而不递增计数器。**两次曝光间隔**控件在红/绿/蓝拍摄之间加入停顿，让较旧的机身能在下一张到来之前完成上一张的写回；这可以避免某些相机在被过快的新拍摄命令接连轰炸时触发的 USB/PTP 卡死。

**窄带扫描。** 由窄带 RGB LED 照明的扫描渲染得比白光扫描更饱和，因为每个通道都在吸收峰附近采样其染料，而宽带光天然的谱重叠缺失了。工艺面板中 **Linear RAW** 旁的**窄带**开关使用随附的 RGBScan 输入配置文件对此进行校正，作用于预览和每一次导出。导出设置中明确指定的**输入 ICC** 在设置期间优先。

### 传感器校准

窄带 RGB 光源下的单次扫描可能呈现出任何滑块都修不掉的色相。黄色偏向橙色是典型征兆。原因是**传感器串扰**：相机的色彩滤镜通带与光源的波段重叠，因此绿色像素看到蓝色 LED 和部分红色，每个通道都带有相邻通道的份额。这是你的传感器与光源组合的固定属性，与胶片无关。

要校正它，在片夹中没有胶片的情况下对裸光拍摄三次：仅红、仅绿、仅蓝。使用与扫描相同的设置，曝光到刚好低于溢出。然后打开**校准**面板，找到*单次窄带校准*，按校准按钮，选择三张拍摄，为配置文件命名并保存。选定的配置文件在反转之前，在线性域用一个 3×3 矩阵对每次扫描进行通道解混。配置文件是 `NegPy/sensor` 文件夹中的 TOML 文件。更改配置文件后，重新运行**批量分析**。

不要将它用于 RGB 三联组（三色）扫描。它们从原理上就没有串扰，因为每个通道来自其自身的单色光曝光，而且 NegPy 会自动跳过对联组素材的校正。专用胶片扫描仪同样没有传感器串扰：Coolscan 的单色 CCD 一次读取一个 LED。它的残余颜色误差是胶片染料串扰，由密度域的**串扰**矩阵处理（见 [CROSSTALK.md](CROSSTALK.md)）。

## 故障排查

| 症状 | 原因 | 解决办法 |
|---|---|---|
| 相机圆点显示**“使用中”**（琥珀色提示） | 另一个程序持有该机身，而一台 PTP 相机只允许一个程序占用。在 macOS 上，持有者是系统相机守护进程，任何监视相机的应用都会唤醒它。该应用常常是**后台同步客户端**——没有窗口也没有通知：已确认作为登录项运行的 Google Drive 会这样做，Dropbox 及类似工具的行为相同。 | 退出该后台应用；如果它自行启动，从**系统设置 → 通用 → 登录项**中移除它。拔出并重新插上线缆也会释放相机，但只维持到该应用再次请求为止。Preview、Photos 和 Image Capture 中任何一个真正打开时也会如此。相机一旦空闲，NegPy 会自行重新连接。 |
| 找不到相机，且没有其他程序在运行 | 机身不在 PC Remote 模式，或者它是大容量存储/MTP 连接。 | 将相机的 USB 连接模式设为 **PC Remote**。 |
| `[-10] Timeout reading from or writing to the port`，且没有其他程序持有相机 | 某个程序在连接期间崩溃了。*相机*仍认为会话是打开的，并拒绝新会话。能自行消除的超时会被静默重试，永远不会到达你面前，因此看到它意味着它没有自行消除。 | 给相机断电重启，或拔出再插回线缆。计算机这一侧做什么都没用。 |
| 实时取景是黑屏 | 机身退出了 PC Remote 模式，或盖着镜头盖。 | 给相机断电重启。 |
| 扫描窗口打开时显示**“无实时取景”**而不是预览 | libgphoto2 中该机身的条目没有预览能力。要么机身确实没有（Sony a6000），要么它以 MTP 模式连接——该模式下任何机身都没有。 | 如果消息中提到 MTP，将相机的 USB 模式设为 **PC Remote** 并重新连接。如果没有，这属于预期行为。扫描照常工作，但你必须在相机上设置构图和对焦，并且校准不可用，因为它要通过实时取景来对准。 |
| 拍摄时提示相机返回了 JPEG 而不是 RAW | 相机的图像质量设置为 JPEG，或 RAW+JPEG 选中了处理过的文件。 | 将图像质量设为**仅 RAW**，然后重试。 |
| 光圈步进器置灰 | 镜头没有电子光圈。 | 属于预期行为。在镜头本身上设置光圈。 |
| 某个设置弹回旧值 | 属性写入是异步的，机身需要一点时间。 | NegPy 会轮询直到数值落定，若始终未落定会记录警告。如果始终未落定，说明该设置在机身当前模式下不可写。试试 **M** 模式。 |
| 检测不到 Scanlight | USB-C 口用错了。 | Scanlight 有两个口，只有一个传数据。另一个仅供电。使用数据口。 |

## 说明与限制

- **仅 USB。** libgphoto2 可以通过网络访问某些相机，但 Sony 机身不行。该选项卡是 USB 联机工作流。
- **仅测试过 Sony 机身**，因为手头的硬件就是它。NegPy 不假定任何厂商：每个控件都是查询得来而非假定的。`iso` 和
  `shutterspeed` 在各处的名称相同。光圈在 Sony 和 Panasonic 上叫 `f-number`，在 Canon、Nikon、Fujifilm、Olympus
  和 Sigma 上叫 `aperture`。RAW 后缀来自相机，照片拍入内存而不是存储卡。Canon 和 Nikon 默认写入存储卡，没有卡就不会拍摄。非常欢迎来自其他品牌的反馈。
- **对焦放大镜取决于厂商。** Sony 把变焦倍率和目标点打包在一个属性里，因此一次单击既放大*又*对准。Canon（`eoszoom`）和
  Nikon（`liveviewimagezoomratio`）把它们分开，且其坐标空间此处未知，因此单击只在机身已经看着的地方放大。其他所有机身完全没有放大镜，该功能会自行禁用。
- **在 macOS 上测试。** Python 部分是可移植的，libgphoto2 是 Linux 优先的项目，因此 Linux 至少同样好。这一点未经验证。
- **速度。** 在 a7C II 上通过 USB 拍一组三张 RGB 约需六秒。其中几乎全部是机身逐张传输的延迟，而不是文件大小。照片在运行中的实时取景会话内拍摄，因此没有逐帧重连。
- **致谢。** R/G/B 时序和曝光校准方法来自
  [rohanpandula/TriRGB](https://github.com/rohanpandula/TriRGB)。光源是
  [jackw01/scanlight](https://github.com/jackw01/scanlight)。相机通过
  [python-gphoto2](https://github.com/jim-easterbrook/python-gphoto2) 驱动。窄带方法遵循 Flückiger 等人关于三色胶片扫描的研究。
